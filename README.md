# Truespace — Учёт финансов барного кейтеринга

Цифровая система финансового учёта для выездного барного кейтеринга и ивент-бизнеса. Заменяет заброшенные Google-таблицы быстрым вводом на площадке за 5 секунд (через Telegram или мобильный веб) и строгим раздельным контролем по 5 счетам.

## 🎯 Решаемая проблема

На мероприятии наличные и безналичные деньги распределяются по разным карманам и счетам (касса бара, сейф владельца, расчётный счёт, эквайринг, переводы на карту). В суматохе на площадке чеки теряются, а записи в таблицы откладываются и забываются. В итоге владелец не знает реальный остаток и маржинальность ивента.

Truespace решает это:
1. **Быстрый ввод за 5 секунд:** бармен или владелец отправляет короткое сообщение в Telegram-бот (например, `3500 лед Корпоратив Т-Банк`) или вводит операцию в 3 тапа с крупного мобильного экрана.
2. **5 раздельных счетов:** раздельный баланс по каждому кошельку + мгновенные внутренние переводы (инкассация/пополнение).
3. **Маржинальность мероприятий:** автоматический расчёт выручки, себестоимости, чистой прибыли и маржи по каждому ивенту.
4. **Масштабируемый стек:** React 18 + TypeScript + Vite + Node.js (Express), архитектура Repository, схема данных на 100% готова к Supabase / PostgreSQL.

## ⚡ Быстрый старт

### Требования
- Node.js >= 20 (проверено на Node.js v24.20.0)
- npm >= 10 (проверено на npm 11.19.0)

### 1. Установка зависимостей
```bash
npm install
```

### 2. Запуск локально
```bash
npm run dev
```
Команда запускает одновременно:
- **Клиентский интерфейс (Vite):** [http://localhost:5173/](http://localhost:5173/)
- **Серверный REST API:** [http://localhost:3001/api](http://localhost:3001/api)
- **Доступ с телефона в локальной сети Wi-Fi:** `http://<твой-локальный-ip>:5173/` (Vite запущен с параметром `--host`)

```bash

npm run typecheck

npm run build
```

## 💼 Счета системы (5 счетов)

| Счёт | Назначение |
|------|-----------|
| **Нал 1 (Касса на площадке)** | Размен барменов, чаевые, мелкие чеки на площадке (лёд, мята, фрукты) |
| **Нал 2 (Сейф / Владелец)** | Сейф в офисе: крупные наличные оплаты от заказчиков, гонорары барменов |
| **Безнал 1 (Основной р/с)** | Официальные платежи по договорам с юрлицами, оптовые закупки алкоголя |
| **Безнал 2 (Резерв / Эквайринг)** | Торговый эквайринг (терминал на выезде) и резервный расчётный счёт |
| **Переводы (Карта СБП)** | Личная карта для мгновенных переводов от гостей за дозаказ коктейлей |

## 🤖 Интеграция с Telegram

В системе работает двусторонний модуль Telegram:

1. **Режим браузерного симулятора (по умолчанию):**
   - Не требует токена бота. Прямо в интерфейсе доступна интерактивная строка быстрой команды.
   - Пример ввода: `3500 лед Корпоратив Т-Банк`, `50000 предоплата Свадьба`, `перевод 10000 нал1 нал2`.
   - NLP-парсер мгновенно определяет сумму, категорию, мероприятие и счёт, и записывает транзакцию в кэш-флоу.

2. **Подключение реального Telegram-бота:**
   - Открой [@BotFather](https://t.me/BotFather) в Telegram и создай нового бота (`/newbot`).
   - Скопируй полученный токен.
   - Создай файл `.env` на основе `.env.example`:
     ```env
     BOT_TOKEN=123456789:ABCdefGhIJKlmNoPQRsTUVwxyZ
     ```
   - Перезапусти `npm run dev`. Бот автоматически начнёт слушать чат и сохранять транзакции.

## 🗄️ Перенос в облако (Supabase / PostgreSQL)

База данных построена по паттерну **Repository** (`IFinanceStore`):
- Локально данные хранятся автономно в `data/truespace.json` и оперативной памяти (`InMemoryStore`), без необходимости поднимать СУБД.
- В файле `src/server/data/supabase.sql` подготовлен готовый DDL-скрипт для Supabase:
  - Таблицы `accounts`, `events`, `categories`, `transactions`.
  - Внешние ключи, индексы и констрейнты целостности двойной записи (доходы, расходы, переводы).
  - Готовый сид демо-данных.

Для перехода в Supabase достаточно скопировать содержимое `src/server/data/supabase.sql` в SQL Editor дашборда Supabase и указать переменные `SUPABASE_URL` и `SUPABASE_KEY` в `.env`.

## 📁 Структура проекта

```
src/
├── client/              # Фронтенд на React 18 + TypeScript (Vite)
│   ├── api/             # Клиент REST API
│   ├── components/      # Модульные компоненты (счета, ввод, аналитика, симулятор)
│   │   ├── accounts/    # Карточки счетов и баннер капитала
│   │   ├── analytics/   # Маржинальность и структура затрат
│   │   ├── entry/       # Мобильный ввод за 5 секунд с нумпадом
│   │   ├── history/     # Журнал транзакций с фильтрами и отменой
│   │   └── telegram/    # Симулятор быстрой строки и статус бота
│   ├── context/         # Реактивный FinanceContext
│   ├── hooks/           # Кастомные хуки данных
│   └── utils/           # Форматирование (рубли ₽, даты ДД.ММ.ГГГГ)
├── server/              # Бэкенд на Node.js (Express + TypeScript)
│   ├── data/            # SQL-миграция Supabase и сиды
│   ├── routes/          # REST API маршруты
│   ├── services/        # Финансовое ядро, аналитика, NLP-парсер
│   ├── storage/         # Паттерн Repository (JSON, InMemory, Supabase)
│   └── telegram/        # Сервис Telegram-бота
└── shared/              # Общие типы данных, DTO и константы
```
