# Переносимость проекта

Цель — чтобы созданный проект можно было запустить на другом компьютере без
догадок и случайного подбора версий.

## До создания приложения

- Не предполагать, что проект обязательно использует npm или JavaScript.
- Сначала определить главное действие и подходящий формат продукта.
- Проверить уже установленные инструменты и не создавать второй проект поверх
  существующего.
- Предпочитать стабильные поддерживаемые технологии с понятной установкой.

## После выбора технологий

- Зафиксировать версию среды выполнения: Node.js, Python или другой платформы.
- Зафиксировать зависимости штатным lock-файлом выбранного менеджера пакетов.
- Не включать в архив зависимости, сборки, кэши, `.env` и другие локальные
  файлы.
- В `README.md` указать требования и команды установки, запуска и проверки.
- Добавлять библиотеку только ради конкретной функции, а не «на всякий случай».
- Избегать beta-, canary- и экспериментальных пакетов, если без них можно
  реализовать главное действие.

## Проверка перед передачей

1. Создать чистую временную копию исходников.
2. Выполнить установку строго по `README.md` и lock-файлу.
3. Запустить форматирование, типы, тесты и сборку, которые есть в проекте.
4. Запустить приложение и пройти главное действие.
5. Убедиться, что в архиве нет секретов, реальных данных и сгенерированных
   каталогов.
6. Проверить, что ошибка несовместимой версии объясняется явно, а не выглядит
   как непонятная ошибка npm или Python.

Если чистая установка не была проверена, нельзя говорить, что проект готов к
передаче на другой компьютер.
