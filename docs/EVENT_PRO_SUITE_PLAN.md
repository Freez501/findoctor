# Архитектурный план: Event Pro Suite для FinDoctor

> **Цель:** Превратить FinDoctor в ультимативный финансовый инструмент для **ивент-индустрии в целом** (организаторы мероприятий, event-агентства, свадебные распорядители, технический продакшн, выездные бары и кейтеринг).
> 
> **Фокус трёх ключевых модулей:**
> 1. **График платежей и Платёжный календарь** — защита от кассовых разрывов при разрыве во времени между предоплатой и расходами.
> 2. **Смета мероприятия: План vs Факт** — контроль перерасхода бюджета по статьям (декор, артисты, площадка, кейтеринг, логистика) в реальном времени.
> 3. **Подрядчики и контроль выплат на площадке (Event Crew & Vendors)** — фиксация гонораров, авансов и остатка к выплате наличными или переводом на демонтаже.

---

## 1. Где и как это запускается: Концепция интеграции в UI

Вместо создания множества разрозненных вкладок мы используем **глубокую интеграцию в уже существующие разделы**, сохраняя простоту и скорость работы за 5 секунд.

```
┌────────────────────────────────────────────────────────────────────────────────────────┐
│                                 ВЕРХНЯЯ НАВИГАЦИЯ                                      │
│  [Счета]   [★ Мероприятия]   [★ Аналитика]   [★ Журнал (Cash Flow)]   [Настройки]     │
└────────────────────────────────────────────────────────────────────────────────────────┘
                    │                 │                  │
                    ▼                 ▼                  ▼
       ┌────────────────────────┐   ┌─────────────────┐   ┌───────────────────────────────┐
       │  КАРТОЧКА МЕРОПРИЯТИЯ  │   │ СВОДНАЯ АНАЛИТИКА │   │     ЖУРНАЛ (CASH FLOW / ДДС)  │
       │   «Досье проекта»      │   │                 │   │                               │
       │ ├─ 1. Смета (План/Факт)│   │ [Маржинальность]│   │ ├─ Фактический поток денег    │
       │ ├─ 2. Подрядчики       │   │        VS       │   │ ├─ Фильтр по счетам и ивентам │
       │ └─ 3. График оплат     │   │ [★ Платёжный    │   │ ├─ Привязка чеков к смете     │
       └────────────────────────┘   │    календарь]   │   │ └─ Быстрый экспорт / импорт   │
                                    └─────────────────┘   └───────────────────────────────┘
```

### Точки входа в интерфейсе:

1. **Вкладка «Мероприятия» (`events`):**
   * В каждой карточке проекта появляется кнопка **«Финансовое досье»** (или разворот карточки по клику).
   * Внутри открывается специализированная панель с 3 вкладками:
     * **Вкладка А: «Смета План-Факт»** — таблица запланированных статей сметы против фактических транзакций с прогресс-барами и цветовыми индикаторами (зелёный — в бюджете, красный — перерасход).
     * **Вкладка Б: «Подрядчики и команда»** — карточки и реестр: кто работает на ивенте (Ведущий, DJ, Декор, Кейтеринг, Свет), какой гонорар согласован, сколько отдано авансом, сколько осталось отдать в конце смены. Кнопка **«Выплатить»** в 1 клик прямо из строки.
     * **Вкладка В: «График поступлений»** — этапы оплаты от заказчика (Аванс, Второй транш, Финальный расчет). Индикаторы «Оплачено», «Ожидается к ДД.ММ», «Просрочено».

2. **Вкладка «Аналитика» (`analytics`):**
   * Добавляется переключатель режимов:
     * **«Маржинальность проектов»** (текущий P&L-анализ мероприятий);
     * **«Платёжный календарь (Cash Flow Forecast)»** — общий календарный график на ближайшие 30–60 дней. Показывает плановые приходы от заказчиков и обязательные платежи подрядчикам. Если график прогнозируемого остатка уходит в минус — загорается предупреждение о кассовом разрыве с датой и суммой дефицита.

3. **Вкладка «Журнал» (`history` / Cash Flow / ДДС):**
   * Это **фактический ДДС (Движение Денежных Средств)** в реальном времени: хронологическая лента всех приходов, расходов и переводов с фильтрацией по счетам, мероприятиям и статьям.
   * Связка со сметой: каждая транзакция расхода с привязкой к ивенту автоматически закрывает соответствующую строчку в смете мероприятия (Факт) и уменьшает остаток задолженности перед выбранным подрядчиком.
   * Экспорт/импорт выписок и пакетные операции.

4. **Модальное окно быстрого ввода (`QuickEntryModal`):**
   * При выборе расхода с привязкой к мероприятию появляется умное поле: *«Кому выплата (подрядчик)?»*.
   * При выборе подрядчика сумма автоматически списывается с остатка его долга в карточке ивента.

## 2. Модели данных (Shared Types & Contracts)

### Модуль 1: Этапы графика платежей (`EventPaymentMilestone`)
```typescript
export interface EventPaymentMilestone {
  id: string;
  eventId: string;
  title: string;          // например: "Аванс 30% (бронь даты)", "Транш 50% (закупки)", "Финальный расчет 20%"
  dueDate: string;        // YYYY-MM-DD
  amount: number;         // сумма этапа в рублях
  status: 'pending' | 'received' | 'overdue';
  paidAmount?: number;    // фактически поступило
  paidDate?: string;      // дата фактического прихода
  notes?: string;
}
```

### Модуль 2: Смета План-Факт (`EventBudgetItem`)
```typescript
export interface EventBudgetItem {
  id: string;
  eventId: string;
  categoryId: string;     // привязка к статье расходов (Декор, Площадка, Звук, Алкоголь и т.д.)
  plannedAmount: number;  // заложено в смету клиенту
  actualAmount: number;   // автоматически суммируется из реальных транзакций
  notes?: string;
}
```

### Модуль 3: Подрядчики и команда на мероприятии (`EventVendor`)
```typescript
export interface EventVendor {
  id: string;
  eventId: string;
  name: string;           // ФИО или название ("DJ Алексей", "Аренда звука Еврошоу")
  role: string;           // "Ведущий", "Звукорежиссер", "Фотограф", "Декоратор", "Монтажники"
  phone?: string;
  agreedFee: number;      // Согласованный общий гонорар
  paidAmount: number;     // Выплачено авансом
  remainingAmount: number;// Остаток к выплате (agreedFee - paidAmount)
  status: 'pending' | 'partial' | 'paid';
  dueDate?: string;       // Дата финального расчета (обычно день монтажа/демонтажа)
}
```

## 3. Детальный пошаговый план реализации

### Этап 1: Доменная модель и хранилище (Бэкенд)
1. Расширить `src/shared/types.ts`:
   - Добавить типы `EventPaymentMilestone`, `EventBudgetItem`, `EventVendor`.
   - Добавить поля в `CateringEvent` для связи с досье.
2. Обновить контракт хранилища `IFinanceStore`:
   - Методы CRUD для смет, подрядчиков и графиков платежей.
3. Реализовать методы в `JsonFileStore` и адаптере `SupabaseStore`:
   - Безопасное сохранение в `data/truespace.json` и DDL миграция для PostgreSQL/Supabase.
4. Добавить REST API роуты:
   - `/api/events/:id/milestones`
   - `/api/events/:id/budget`
   - `/api/events/:id/vendors`
   - `/api/analytics/cashflow-calendar`

### Этап 2: Досье проекта в интерфейсе («Мероприятия»)
1. Создать компонент `EventDossierModal.tsx` (или встроенную раскрывающуюся панель `EventDetailsCard.tsx`):
   - Табы: **«Смета План-Факт»**, **«Подрядчики»**, **«График оплат»**.
2. Реализовать **Смету План/Факт**:
   - Строки по категориям, сравнение сметы и факта, процент использования бюджета, предупреждение о перерасходе.
3. Реализовать **Реестр подрядчиков**:
   - Карточки специалистов, бейджи статуса оплаты, кнопка быстрой выплаты остатка.
4. Реализовать **График оплат**:
   - Список траншей, расчет дебиторки, отметка о получении транша.

### Этап 3: Сводный Платёжный Календарь («Аналитика»)
1. Создать компонент `CashFlowCalendar.tsx`:
   - Календарная сетка / таймлайн на текущий и следующий месяц.
   - Суммирование ожидаемых приходов и расходов на каждый день.
   - График остатка денег на счетах с линией нулевого баланса (радар кассовых разрывов).
2. Подсветка рискованных дат:
   - Если остаток на счетах компании падает ниже безопасного буфера — блок с предупреждением: *«25 октября дефицит 85 000 ₽: запланирована оплата декора, а финальный транш от заказчика придёт только 28 октября»*.

### Этап 4: Интеграция с быстрым вводом и проверка
1. Доработать `QuickEntryModal`:
   - Выбор подрядчика при расходе по мероприятию с автозаполнением суммы остатка.
2. Добавить тесты ядра (`vitest`):
   - Проверка математики остатков подрядчиков.
   - Проверка расчета перерасхода сметы.
   - Проверка детектора кассовых разрывов.
3. Визуальная проверка в браузере (мобильный 375px и десктоп 1440px).

## 4. Демонстрационный сценарий (Acceptance Criteria)

1. **Создание ивента:** Создаём проект *«Свадьба Артёма и Алины»* на 650 000 ₽.
2. **График платежей:** Назначаем 3 этапа: Аванс 200 000 ₽ (получен), Доплата 300 000 ₽ (через 2 недели), Финал 150 000 ₽ (в день ивента).
3. **Смета:** Закладываем в смету: Площадка (150 000 ₽), Декор (120 000 ₽), Звук/Свет (70 000 ₽), Бар (90 000 ₽).
4. **Подрядчики:** Добавляем *DJ Сергей* (гонорар 35 000 ₽, аванс 10 000 ₽, остаток 25 000 ₽).
5. **Выплата в 1 клик:** Нажимаем «Выплатить остаток 25 000 ₽» → операция проводится с кассы «Нал 1» → остаток DJ обнуляется → в смете факт по звуку увеличивается на 25 000 ₽.
6. **Календарь разрывов:** В аналитике видим точную дату, когда деньги на счетах будут на минимуме, и подтверждаем отсутствие дефицита.
