# Публикация тестовой версии

> Это общий безопасный маршрут. Перед публикацией Codex уточняет фактический
> стек и создаёт конкретные команды для выбранной платформы.

## Когда публиковать

Сначала локальная версия должна запускаться, основной сценарий — проходить, а
сборка и доступные тесты — завершаться без ошибок. Для первого публичного демо
используются только демонстрационные данные.

## Что Codex делает до подтверждения

1. Проверяет сборку, `.gitignore`, отсутствие секретов и реальных данных.
2. Предлагает один рекомендуемый сервис, доступный пользователю из России.
3. Проверяет на официальном сайте текущую цену, способ оплаты, регион данных,
   HTTPS, технический домен, лимит расходов и способ удаления проекта.
4. Объясняет, что станет публичным, возможные расходы и способ отката.
5. Просит явное подтверждение публикации.

## После подтверждения

Codex ведёт человека по одному действию за раз:

1. Подготавливает Git-репозиторий без секретов.
2. Помогает создать внешний ресурс, не запрашивая пароль или токен в чате.
3. Настраивает сборку и публикацию.
4. Проверяет публичную ссылку в чистой сессии браузера и на мобильном размере.
5. Записывает адрес и способ остановки публикации в `PROJECT.md`.
6. Даёт готовое сообщение для первых 3–5 пользователей.

Автоматическую публикацию каждого изменения не включать на первом шаге. Сначала
пользователь должен увидеть связь между локальной и публичной версиями.

## Если публикация не удалась

Не выполнять автоматические разрушительные откаты. Сначала сохранить логи,
определить, осталась ли предыдущая версия доступной, и объяснить ситуацию
простыми словами. Затем исправить причину и повторить проверку. Если требуется
удаление ресурса, данных или платное действие — снова получить подтверждение.

## Рабочий продукт

Публичное демо не считается готовым рабочим продуктом. Перед реальными данными
отдельно проверить авторизацию, права доступа, резервные копии, мониторинг,
обработку персональных данных и порядок восстановления.
