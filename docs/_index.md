# Карта документации проекта

## Главные файлы

- `AGENTS.md` — постоянные правила работы Codex и сопровождения пользователя.
- `README.md` — короткий вход для человека, который впервые открыл папку.
- `PROJECT.md` — актуальная карточка, состояние, проверки и следующий шаг.

## `docs/core/` — правила и термины

- `WORKFLOW_RULES.md` — простой цикл разработки и границы подтверждений.
- `GLOSSARY.md` — словарь продуктовых терминов; заполняется по мере появления
  устойчивых понятий.
- `DESIGN_SYSTEM.md` — общий дизайн-процесс и необязательный React-пресет.
- `PORTABILITY.md` — правила версий, зависимостей и проверки на чистой копии.
- `MATH_MODEL.md` — создаётся только если продукту действительно нужны формулы,
  расчёты или строгие бизнес-инварианты; для каждого проекта не обязателен.
- `ARCHITECTURE.md` и `TECH_STACK.md` — создаются, когда проект становится
  достаточно сложным, чтобы эти решения нельзя было надёжно увидеть из кода.

## `docs/decisions/` — важные решения

Шаблон `_template.md` используется для дорогих, рискованных или трудно
обратимых решений. Не нужно создавать отдельный документ для каждой мелкой
правки.

## `docs/specs/` — большие функции

Спецификация и план создаются только для достаточно крупной функции. Маленькие
изменения выполняются коротким циклом из `WORKFLOW_RULES.md`.

## `docs/runbooks/` — эксплуатация

Здесь находятся инструкции публикации, восстановления и устранения проблем.
Перед использованием старого runbook Codex обязан проверить, соответствует ли
он фактическому стеку и выбранному хостингу.

- `local-network-preview.md` — безопасный просмотр с телефона или другого
  компьютера в одной домашней сети.
- `deploy.md` — переход от локального прототипа к публичному демо.
