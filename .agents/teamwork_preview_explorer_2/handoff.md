### 2.2. Операции и формулы пересчёта балансов (Transaction State Transitions)

Каждая транзакция $T$ представляет собой кортеж:
$$T = \langle id, type, amount, fromAccountId?, toAccountId?, eventId?, categoryId, date, isDeleted \rangle$$
где $amount > 0$.

#### 1. Доход (`type: 'income'`)
- **Условие:** Обязательно указан счёт зачисления $toAccountId$. Счёт списания $fromAccountId = \text{null}$.
- **Влияние на баланс счёта:**
  $$Balance(toAccountId)' = Balance(toAccountId) + amount$$
- **Влияние на мероприятие:**
  $$\text{Если } eventId \neq \text{null}: \quad Revenue(eventId)' = Revenue(eventId) + amount$$
  $$\text{Если } eventId = \text{null}: \quad \text{Операция относится к общему внереализационному доходу бара.}$$
- **Влияние на общий капитал бизнеса:**
  $$\Delta TotalCapital = +amount$$

#### 2. Расход (`type: 'expense'`)
- **Условие:** Обязательно указан счёт списания $fromAccountId$. Счёт зачисления $toAccountId = \text{null}$.
- **Влияние на баланс счёта:**
  $$Balance(fromAccountId)' = Balance(fromAccountId) - amount$$
- **Влияние на мероприятие:**
  $$\text{Если } eventId \neq \text{null}: \quad DirectExpenses(eventId)' = DirectExpenses(eventId) + amount$$
  $$\text{Если } eventId = \text{null}: \quad \text{Операция относится к общехозяйственным расходам (аренда склада, хозтовары).}$$
- **Влияние на общий капитал бизнеса:**
  $$\Delta TotalCapital = -amount$$

#### 3. Перевод между счетами (`type: 'transfer'`)
- **Условие:** Указаны оба счёта: $fromAccountId$ и $toAccountId$, причём $fromAccountId \neq toAccountId$.
- **Влияние на балансы счетов:**
  $$Balance(fromAccountId)' = Balance(fromAccountId) - amount$$
  $$Balance(toAccountId)' = Balance(toAccountId) + amount$$
- **Влияние на мероприятие:**
  $$\Delta Revenue(E) = 0, \quad \Delta DirectExpenses(E) = 0$$
  Перевод — это чистое перемещение ликвидности между карманами бизнеса (инкассация с площадки в сейф, снятие наличных со счёта, перевод с СБП-карты на расчётный счёт). Он **не изменяет** финансовый результат мероприятий.
- **Влияние на общий капитал бизнеса:**
  $$\Delta TotalCapital = (+amount) + (-amount) \equiv 0 \quad \text{(Закон сохранения суммарного капитала)}$$

### 2.3. Инварианты финансового ядра (Core Financial Invariants)

1. **Инвариант баланса отдельного счёта ($A_i$):**
   $$Balance(A_i) = InitialBalance(A_i) + \sum_{\substack{t \in T_{\text{active}} \\ t.toAccountId = A_i}} t.amount - \sum_{\substack{t \in T_{\text{active}} \\ t.fromAccountId = A_i}} t.amount$$

2. **Глобальный инвариант сохранения капитала:**
   Сумма остатков по всем 5 счетам в любой момент времени $t$ строго равна сумме начальных остатков плюс сумма всех проведённых доходов минус сумма всех проведённых расходов:
   $$\sum_{i=1}^{5} Balance(A_i) \equiv \sum_{i=1}^{5} InitialBalance(A_i) + \sum_{t \in T_{\text{active}}^{\text{income}}} t.amount - \sum_{t \in T_{\text{active}}^{\text{expense}}} t.amount$$
   *Следствие:* ни одна внутренняя операция перевода (`transfer`) не может изменить значение правой части равенства.

3. **Инвариант обратимости (Отмена / Удаление транзакции):**
   При удалении или отмене транзакции $T$ (пометка `isDeleted = true` либо удаление из активного журнала) применяется строгая инверсная функция $\mathcal{T}^{-1}$:
   - Для Дохода:
     $$Balance(toAccountId)' = Balance(toAccountId) - amount$$
     $$\text{Если } eventId \neq \text{null}: \quad Revenue(eventId)' = Revenue(eventId) - amount$$
   - Для Расхода:
     $$Balance(fromAccountId)' = Balance(fromAccountId) + amount$$
     $$\text{Если } eventId \neq \text{null}: \quad DirectExpenses(eventId)' = DirectExpenses(eventId) - amount$$
   - Для Перевода:
     $$Balance(fromAccountId)' = Balance(fromAccountId) + amount$$
     $$Balance(toAccountId)' = Balance(toAccountId) - amount$$
   *Гарантия целостности:* После выполнения последовательности $\mathcal{T}^{-1}(\mathcal{T}(S, T), T)$ состояние $S'$ идентично исходному состоянию $S$.

4. **Защита от погрешностей с плавающей точкой в JS/TS:**
   Все финансовые величины в TypeScript должны рассчитываться либо в целых копейках ($amountInCents = \text{Math.round}(amount \times 100)$), либо с нормализацией округления:
   $$\text{round2}(x) = \frac{\text{Math.round}(x \times 100)}{100}$$
   Это исключает накопление артефактов IEEE-754 (например, $0.1 + 0.2 = 0.30000000000000004$).

### 2.4. Аналитика маржинальности мероприятий (Event Margin Analytics)

Для каждого мероприятия $E$:

1. **Выручка мероприятия ($Revenue$):**
   $$Revenue(E) = \sum_{\substack{t \in T_{\text{active}} \\ t.eventId = E.id \\ t.type = 'income'}} t.amount$$

2. **Прямые расходы мероприятия ($DirectExpenses$):**
   $$DirectExpenses(E) = \sum_{\substack{t \in T_{\text{active}} \\ t.eventId = E.id \\ t.type = 'expense'}} t.amount$$

3. **Чистая прибыль мероприятия ($NetProfit$):**
   $$NetProfit(E) = Revenue(E) - DirectExpenses(E)$$

4. **Маржинальность мероприятия ($Margin\%$):**
   $$Margin\%(E) = \begin{cases} \left( \frac{NetProfit(E)}{Revenue(E)} \right) \times 100\%, & \text{если } Revenue(E) > 0 \\ 0.00\%, & \text{если } Revenue(E) = 0 \text{ и } DirectExpenses(E) = 0 \\ \text{Отрицательная (-100% / N/A)}, & \text{если } Revenue(E) = 0 \text{ и } DirectExpenses(E) > 0 \end{cases}$$

5. **Категории расходов и структура себестоимости:**
   Каждый прямой расход относится к одной из производственных категорий:
   - `alcohol` («Алкоголь и напитки»)
   - `staff` («Персонал и гонорары»)
   - `logistics` («Логистика и транспорт»)
   - `supplies` («Лёд и продукты — фрукты, пюре, сиропы»)
   - `equipment` («Аренда оборудования и посуды»)

   Доля категории в прямых расходах:
   $$CategoryShare(E, C) = \frac{\sum_{t \in T_{\text{active}}^{\text{expense}}(E, C)} t.amount}{DirectExpenses(E)} \times 100\%$$
   Инвариант: $\sum_{C} CategoryShare(E, C) \equiv 100.00\%$.

6. **Пороговые шкалы маржинальности для интерфейса:**
   - **Высокая маржинальность (Зелёный индикатор):** $Margin\% \ge 60\%$ (норма для барного кейтеринга премиум-уровня).
   - **Средняя маржинальность (Жёлтый индикатор):** $40\% \le Margin\% < 60\%$ (стандартные масштабные банкеты с высокой долей дорогого алкоголя).
   - **Низкая маржинальность / Риск (Красный индикатор):** $0\% \le Margin\% < 40\%$ (перерасход алкоголя, повышенные транспортные расходы, необходимость пересмотра сметы).
   - **Убыток (Тёмно-красный индикатор):** $Margin\% < 0\%$ (прямые расходы превысили поступившую выручку).
   - **Подготовка к мероприятию (Серый нейтральный индикатор):** $Revenue = 0$ при наличии расходов (закупки перед получением финальной оплаты).

## 5. Caveats (Ограничения и допущения)

1. **Многовалютность:** В соответствии с требованиями первой версии, базовой валютой является российский рубль (`RUB`). Мультивалютная конвертация в реальном времени исключена из MVP.
2. **НДС и налоги:** Формулы маржинальности рассчитывают операционную маржу кейтеринга до вычета УСН/патента и комиссий банков за эквайринг (эквайринговые комиссии при необходимости проводятся отдельным расходом с категории `overhead`).
3. **Отрицательные балансы:** В реальной жизни касса на площадке не может выдать больше наличных, чем в ней лежит. Система должна выводить предупреждение при попытке списать сумму, превышающую текущий остаток счёта, однако для гибкости фиксации в полевых условиях блокировать операцию не следует (с индикацией отрицательного остатка красным цветом).
4. **Складской учёт:** В соответствии с `PROJECT.md`, списание ингредиентов в миллилитрах и граммах не ведётся; фиксируются прямые финансовые расходы на закупку алкоголя и продуктов по чекам/накладным.
